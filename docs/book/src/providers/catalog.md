# Provider Catalog

Every model-provider family ZeroClaw ships with. For each: config shape, notes on auth and endpoint behavior, and the slot key to use under `[providers.models.<type>.<alias>]`.

See [Configuration](./configuration.md) for universal fields (`api_key`, `uri`, `model`, ...) and resolution order.

> Examples below use `home` as the alias to underline that the alias half is operator-chosen, pick whatever name fits (`work`, `personal`, `cn`, `prod`, ...). Reference it from an agent via `model_provider = "<type>.<alias>"`.

---

## Native

### Anthropic / Claude: slot `anthropic`

Supports Console API keys and tokens generated by `claude setup-token` for Claude Max. Both credential forms live on the canonical `anthropic` slot's `api_key` field; Quickstart exposes them as `api_key` and `setup_token` choices. Streaming, tool calls, vision, and reasoning all supported. Custom endpoints (Anthropic-compatible proxies, e.g. Z.AI's Anthropic API) go on this slot too: set `uri` to override.

### OpenAI: slot `openai`

GPT-4o, GPT-5, o-series reasoning models. When reasoning is streamed, it is carried in the optional `reasoning` field of a `StreamChunk` wrapped by `TextDelta`; see [Streaming](./streaming.md).

### OpenAI Codex: `openai` slot with `requires_openai_auth = true`

OpenAI Codex subscription auth lives on the `openai` slot. Set `wire_api = "responses"` to route through `POST /v1/responses` and `requires_openai_auth = true` to use the Codex subscription login (from the Codex CLI's own `~/.codex/auth.json`) instead of an `api_key` field on the entry. The subscription path does not read `OPENAI_API_KEY`; that variable applies only to the metered `openai` API-key mode. See [Provider Configuration → OAuth and subscription auth](./configuration.md#oauth-and-subscription-auth) for the credential model.

### Gemini: slot `gemini`

Google's Gemini API. Supports vision and pre-executed grounded search (see [Streaming](./streaming.md) for `PreExecutedToolCall` events).

## OpenAI-compatible: Ollama

Use slot `ollama` for local or remote inference through `/v1/chat/completions`.
The local default is `http://localhost:11434/v1`. An explicit `api_key` is sent
as a bearer token; without one, requests omit the authorization header.
See [Ollama configuration](./configuration.md#ollama) for URL handling and
the retired native `/api/chat` options.

## Multi-region families

Some vendors expose distinct regional endpoints with different default models. Use one canonical slot and pick the region with the typed `endpoint` field on the alias entry.

### Qwen / DashScope: slot `qwen`

OAuth-backed Qwen accounts use the same slot with `auth_mode = "oauth"`.

### MiniMax: slot `minimax`

```toml
[providers.models.minimax.intl]
model    = "MiniMax-M3"                       # or MiniMax-M2.7, MiniMax-M2.7-highspeed
api_key  = "..."
endpoint = "intl"                            # variants: cn, intl
```

## Routing layers

OpenRouter is reached through a `custom` (OpenAI-compatible) slot pointed at `https://openrouter.ai/api/v1`, not a dedicated family. The runtime still sees one endpoint; OpenRouter handles vendor fan-out behind that endpoint.

For per-task routing, run multiple agents and let channels pick which agent handles which traffic, see [Routing](./routing.md). For a narrower in-config hint mechanism, use `[[model_routes]]`.

## Retired preset families

These families were thin URL presets over the shared OpenAI-compatible client and no
longer have a slot. Point a `custom` slot at the endpoint instead, with `uri` set to the
former default below:

```toml
[providers.models.custom.home]
uri     = "https://api.mistral.ai/v1"
model   = "..."
api_key = "..."
```

A config that still declares `[providers.models.<retired>.<alias>]`, references
`<retired>.<alias>` from an agent, route, or fallback, or sets a
`ZEROCLAW_providers__models__<retired>__...` override fails to load with an error that
names the replacement. Keys and endpoints are never migrated automatically. `sglang`,
`vllm`, and `litellm` were local-server presets: use `custom` (or `llamacpp`) with your
server's own URL.

## Something missing?

- If the endpoint is OpenAI-compatible, use the `custom` slot with `uri` set.
- If it has its own canonical slot above, use that, even if you only see one of its regions, the slot's `endpoint` enum covers the rest.
- If it speaks a non-OpenAI wire format and needs its own implementation, see [Custom providers](./custom.md).
